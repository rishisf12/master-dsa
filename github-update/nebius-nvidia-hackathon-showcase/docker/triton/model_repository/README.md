# Triton Model Repository

This directory contains model configurations for Triton Inference Server.

## Structure

```
model_repository/
├── tensorrt_llm/           # TensorRT-LLM optimized LLM
│   ├── config.pbtxt       # Model configuration
│   └── 1/                 # Model version 1 (engine files go here)
│       ├── config.json    # TensorRT-LLM engine config
│       ├── rank0.engine   # Compiled engine (generated)
│       └── tokenizer/     # Tokenizer files
└── embeddings/            # Embedding model (optional)
    ├── config.pbtxt
    └── 1/
```

## TensorRT-LLM Model Setup

### 1. Build the TensorRT-LLM Engine

```bash
# Clone TensorRT-LLM
git clone https://github.com/NVIDIA/TensorRT-LLM.git
cd TensorRT-LLM

# Build the engine for your model (example: Llama-3-70B)
# This requires the model weights and significant GPU memory
python examples/llama/build.py \
  --model_dir /path/to/llama-3-70b \
  --output_dir /models/tensorrt_llm/1 \
  --dtype fp8 \
  --tp_size 1 \
  --max_batch_size 32 \
  --max_input_len 4096 \
  --max_output_len 2048 \
  --use_fused_mlp \
  --use_paged_kv_cache \
  --enable_fp8
```

### 2. Copy Tokenizer

```bash
# Copy tokenizer files to model directory
cp /path/to/llama-3-70b/tokenizer* /models/tensorrt_llm/1/
cp /path/to/llama-3-70b/special_tokens_map.json /models/tensorrt_llm/1/
cp /path/to/llama-3-70b/tokenizer_config.json /models/tensorrt_llm/1/
```

### 3. Verify Engine Config

The engine config (`config.json`) should be generated by the build script. Example:

```json
{
  "model_architecture": "LlamaForCausalLM",
  "dtype": "fp8",
  "num_layers": 80,
  "num_heads": 64,
  "num_kv_heads": 8,
  "hidden_size": 8192,
  "vocab_size": 128256,
  "max_position_embeddings": 8192,
  "head_size": 128,
  "tensor_parallelism": 1,
  "pipeline_parallelism": 1,
  "max_batch_size": 32,
  "max_input_len": 4096,
  "max_output_len": 2048,
  "max_beam_width": 1,
  "max_seq_len": 6144,
  "tokens_per_block": 64,
  "max_tokens_in_paged_kv_cache": 8192,
  "quantization": {
    "quant_algo": "FP8",
    "kv_cache_quant_algo": "FP8"
  }
}
```

## Deploying to Triton

### Local Docker

```bash
# Start Triton with model repository
docker run --gpus all -p 8000:8000 -p 8001:8001 -p 8002:8002 \
  -v $(pwd)/model_repository:/models \
  nvcr.io/nvidia/tritonserver:24.08-py3 \
  tritonserver --model-repository=/models
```

### Verify Model Load

```bash
# Check model status
curl localhost:8000/v2/models/tensorrt_llm

# Check model readiness
curl localhost:8000/v2/models/tensorrt_llm/ready
```

### Test Inference

```bash
# Using tritonclient
python -c "
import tritonclient.http as httpclient
import numpy as np

client = httpclient.InferenceServerClient('localhost:8000')

# Prepare input
input_ids = np.array([[1, 2, 3, 4, 5]], dtype=np.int32)
input_lengths = np.array([[5]], dtype=np.int32)
request_output_len = np.array([[50]], dtype=np.uint32)

inputs = [
    httpclient.InferInput('input_ids', input_ids.shape, 'INT32'),
    httpclient.InferInput('input_lengths', input_lengths.shape, 'INT32'),
    httpclient.InferInput('request_output_len', request_output_len.shape, 'UINT32'),
]
inputs[0].set_data_from_numpy(input_ids)
inputs[1].set_data_from_numpy(input_lengths)
inputs[2].set_data_from_numpy(request_output_len)

outputs = [httpclient.InferRequestedOutput('output_ids')]

result = client.infer('tensorrt_llm', inputs, outputs=outputs)
output_ids = result.as_numpy('output_ids')
print(f'Generated: {output_ids.shape}')
"
```

      - name: models

## Model Optimization Tips

### For Lower Latency
- Use FP8 quantization (default)
- Enable speculative decoding with a draft model
- Reduce max_batch_size for lower latency at cost of throughput
- Use `--enable_chunked_context` for long contexts

### For Higher Throughput
- Increase max_batch_size
- Use tensor parallelism (tp_size > 1) on multi-GPU
- Enable in-flight batching (default)
- Use KV cache optimization

### Memory Optimization
- Use INT4/AWQ quantization for smaller models
- Reduce `max_tokens_in_paged_kv_cache`
- Adjust `kv_cache_free_gpu_mem_fraction`

## Troubleshooting

### Model fails to load
1. Check Triton logs: `docker logs <container>`
2. Verify engine files exist in version directory
3. Check config.pbtxt syntax
4. Ensure GPU memory is sufficient

### Out of memory
1. Reduce max_batch_size
2. Reduce max_input_len/max_output_len
3. Use stronger quantization (INT4)
4. Enable KV cache compression

### High latency
1. Check if batching is working (nv_infer_queue_duration_us)
2. Verify GPU utilization (nvidia-smi)
3. Check for CPU preprocessing bottlenecks
4. Profile with Nsight Systems
